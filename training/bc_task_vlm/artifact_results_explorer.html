What each metric means

Every value is a per-step teacher-forced accuracy: given the ground-truth history and the current camera view, predict the expert's next tool call. The tag shows the denominator — which steps the metric is scored over.

The headline. A 3-epoch LoRA fine-tune of an 8B model reaches .878 judged-overall in its native tool-calling format — beating the best frontier out-of-the-box configuration (.655) and its own un-tuned base on the identical native interface (.367). Adding supervised per-step rationales in v1.5 reaches .908 on its fresh held-out-trajectory manifest and .686 on tasks it never trained on.

What prompting could not buy. Across every out-of-the-box configuration — four models, task specifications, worked examples, reasoning budgets, temperature, both answer interfaces — not one completed a single full trajectory. The gap was never manipulation; it was the inter-agent communication protocol (out-of-the-box comm-judged tops out ≈ .37; fine-tuning reaches .717 in v1 and .769 with v1.5 reasoning supervision). That convention is learnable only from the demonstrations.

Fine-tuning subsumes prompt engineering — and then a worked example hurts. Holding the interface at forced JSON, prompt aids barely move the 8B base (.247 → .290 at best, never a trajectory); for the fine-tuned model the task spec adds a little (.868 → .878, trajectories 12% → 16%), and a worked example collapses it (.868 → .550, trajectories → 0): the example pushes the prompt off the distribution it was trained on. In its trained native format the bare baseline reaches the same .878 with more trajectories (17%) and no prompt aid at all — the best configuration is simply the model in its own format.

It is not an interface artifact. We ran the full interface 2×2 on the 8B model — {base, fine-tuned} × {forced JSON, native tool calls}. Native wins every cell, so the headline is the model’s genuine best interface, not a favorable one: the un-tuned base gains most per step (action-exact .405 → .602 / .284 → .432) yet completes zero trajectories at either interface, while the fine-tuned model’s native gain lands where it matters — held-out-task trajectory completion triples, .080 → .253. The frontier control agrees: giving Gemini-3.5 Flash native function calling lowered it slightly (.655 → .635, trajectories still 0.000). No interface rescues an out-of-the-box model, and the practical conclusion for training is to supervise and evaluate in the native tool-calling format. All four 8B cells and the Gemini pair are in the interface view.

Reasoning supervision is a modest, mixed extension. v1.5 supervises a short rationale before each native tool call. Relative to the v1 aggregate, it improves judged-overall from .878 → .908 on trained tasks and .675 → .686 on never-trained tasks; communication rises .717 → .769 and .674 → .687. Full-trajectory transfer is mixed: 17% → 20% on trained tasks but 25% → 20% on held-out tasks. Because v1.5 used a fresh stratified 75-trajectory manifest, these are aggregate—not paired—deltas.

A metric caveat worth stating. The verbatim variant of full-trajectory correctness reads 0.000 for every model including the fine-tuned one, because free-text communicate messages never match word-for-word. The judged version (physical steps exact, communicate steps judge-equivalent) is the honest measure; the verbatim one measures the metric's strictness, not the model.

Held-out tasks are bimodal

Beverage organization, clustering, and meat-skewer assembly are 45/45 native successes. Garnish cake and hot-dog setup are 0/30. The split average therefore hides two qualitatively different failure modes.

The trajectory gap is downstream of planning

On held-out trajectories, FSM-only runs have manipulation-tool similarity 0.963 versus 0.968 for native successes. The model often reaches the intended symbolic state but the simulator’s geometric or temporal predicate remains false.

Expert resemblance is not physical success

Held-out trajectories exactly match the expert manipulation-tool sequence in 48/75 cases and the full object/fixture signature in 39/75, yet native success is only 22/75. Native and symbolic outcomes must remain separate.

Protocol. vLLM backend; Qwen3-VL-8B active-observation causal adapter; causal-cache-centralized observation mode; EGL; two-pass views; distractor-pruned scenes matching data generation. Both final runs have zero harness errors, no null native checks, no native exceptions, and no CUDA failures. Schema-invalid model proposals were safely rejected (26 on held-out tasks; 3 on held-out trajectories).

Reading the metrics. Native success is RoboCasa’s simulator predicate. FSM goal is the verified task specification’s symbolic state after accepted actions. Agreement is diagnostic—not a third success oracle. A simulator executor can report a skill call as successful even when the final placement tolerance, gripper-distance check, or temporal interaction required by the native task is not satisfied.

Expert-similarity caveat. The paired data-generation metadata records per-tool executor success, not a trajectory-level RoboCasa native-success certificate. Matching an expert manipulation sequence therefore demonstrates plan imitation; it does not by itself certify the final geometric or temporal state.
